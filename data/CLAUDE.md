# data/ — синтетические данные и генератор

> **В этом проекте только синтетика.** Никаких реальных биометрических данных, никаких подключений к Apple Health / Google Fit. Этическое требование, не техническое.

---

## Что здесь должно быть

```text
data/
├── generator.py           # Параметризованный генератор биометрических окон
├── scenarios/
│   ├── calm_day.json      # Спокойный день
│   ├── metro_rush.json    # Поездка в метро в час пик (нарастающий стресс)
│   └── school_recess.json # Перемена в школе (шум, толпа)
├── synthetic.csv          # Уже сгенерированный датасет для обучения ML
└── sample_session.json    # Пример одной сессии для тестов
```

---

## Логика генератора

Генератор моделирует трёх "виртуальных пользователей":

1. **Спокойный пользователь** — пульс 70±5, HRV ≈ baseline, accel низкий.
2. **Пользователь с нарастанием стресса** — постепенное падение HRV на 30-50%, рост пульса на 15-25%, рост вариации accel.
3. **Пользователь в критическом состоянии** — резкое падение HRV >50%, всплески accel (микротики), GSR slope растёт.

На каждое окно (60 секунд) присваивается метка по правилам из `docs/data-model.md`.

## Сценарии для демо

Каждый JSON-сценарий описывает временную траекторию состояния:

```text
{
  "name": "metro_rush",
  "duration_minutes": 30,
  "phases": [
    { "start_min": 0,  "end_min": 5,  "state": "calm" },
    { "start_min": 5,  "end_min": 15, "state": "rising_slow" },
    { "start_min": 15, "end_min": 25, "state": "rising_fast" },
    { "start_min": 25, "end_min": 30, "state": "critical" }
  ]
}
```

Генератор читает сценарий и выдаёт поток сэмплов в нужной траектории. Это то, что демонстрируется жюри во время питча.
