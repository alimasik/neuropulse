# docs/ — продуктовая и техническая документация

Все знания о проекте, которые не выводятся из кода. Claude Code **обязан** читать релевантные файлы перед изменениями в соответствующих слоях.

## Что где лежит

| Файл | Когда читать |
| --- | --- |
| `case-context.md` | Перед любым продуктовым решением — это исходный кейс хакатона |
| `architecture.md` | Перед добавлением нового модуля, эндпоинта или потока данных |
| `ux-guidelines.md` | **Перед любой работой с UI** (frontend/) — критично для оценки доступности |
| `data-model.md` | Перед изменением схем API, БД или формата биометрических данных |

## Правила работы с документацией

1. **Документация — source of truth.** Если код противоречит документу — обновляется код, не документ (если нет явного решения изменить требования).
2. **При архитектурном решении — обнови `architecture.md`.** Не оставляй знание только в коде.
3. **Не плоди новые файлы без необходимости.** Расширяй существующие.
4. **Все правки в `ux-guidelines.md` требуют подтверждения пользователя** — это медицинский продукт, инклюзивные требования не угадываются.
