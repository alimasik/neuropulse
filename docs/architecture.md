   └──────────┬───────────┘
              │  JSON (батч 30-60 сек)

   ┌──────────────────────┐         ┌──────────────────────────┐

## Модули

### 1. Data Layer (`data/`)
- **Генератор синтетики** — симулирует поток биометрии "нормального" пользователя и "пользователя в нарастающем стрессе". На вход — сценарий, на выход — JSON-стрим или CSV.
- **Сценарии** — заранее заготовленные траектории для демо (например, "поездка в метро в час пик").

### 2. ML Core (`ml_core/`)
- **Feature extractor** — из сырого окна (60 сек биометрии) считает фичи. **Канонический список фичей — в `docs/data-model.md`** (раздел «Фичи для ML»). Архитектура не дублирует этот список во избежание расхождений.
- **Baseline model** — обученная заранее модель (RandomForest на MVP, XGBoost — если успеем). Класс 0 — норма, 1 — нарастание стресса, 2 — высокий риск срыва.
- **Inference** — синхронный, на CPU. Без GPU.

### 3. Backend (`backend/`)
- **FastAPI** — единственный сервис. Без микросервисов.
- **SQLite** — единственная БД. Подключается через SQLAlchemy.
- **Эндпоинты:**
  - `POST /ingest` — приём окна биометрии (батч). Сохраняет в БД, возвращает 202.
  - `POST /predict` — синхронный инференс на переданном окне. Возвращает `{label, confidence, recommended_action}`.
  - `GET /history?user_id=…` — история эпизодов и предсказаний.
  - `GET /export?user_id=…&format=pdf|csv` — экспорт для врача.
  - `POST /feedback` — пользователь подтверждает корректность предсказания («Я в порядке» / «Помогло»). Пишет в БД.

> WebSocket для live-стрима **не входит в MVP**. Frontend обновляет состояние через HTTP-поллинг `/predict` раз в 10 секунд во время демо.

### 4. Frontend (`frontend/`)
- **Vite + React + TS** — одностраничное SPA, эмулирующее мобильный UI на десктопе.
- **Маршруты:**
  - `/` — главный экран (статус + волновой индикатор).
  - `/intervention` — экран интервенции (триггерится при `label >= 1`).
  - `/map` — Sensory Map.
  - `/aac` — невербальный режим коммуникации.
  - `/doctor` — дашборд для врача/родителя.

### 5. Scripts (`scripts/`)
- Скрипты запуска (`dev.sh`/`dev.bat`), сидинг БД, генерация датасета для обучения, обучение модели.

## Потоки данных (User Journey + Tech)

### Поток 1. Нормальный мониторинг
```
Wearable → /ingest (батч 60с) → SQLite
                ↓
            /predict (фоновый, по таймеру) → label=0 → UI показывает "Стабильно"
```

### Поток 2. Предиктивное предупреждение
```
Wearable → /ingest → /predict → label=1 (нарастание)
                                    ↓
         Frontend получает уведомление → переход на /intervention
                                    ↓
         Пользователь выбирает действие (дыхание / тихий маршрут)
                                    ↓
         Событие логируется в episodes → виден врачу в дашборде
```

### Поток 3. Экстренный режим (AAC)
```
Пользователь нажимает SOS → /aac → крупные карточки для прохожих
                              ↓
                          Опционально: пуш близкому
```

### Поток 4. Аналитика для врача
```
Врач/родитель открывает /doctor → /history → /export?format=pdf
```

## Что НЕ входит в архитектуру MVP

- ❌ Микросервисы. Один FastAPI процесс на всё.
- ❌ Очереди (Kafka/RabbitMQ).
- ❌ Облачное хранилище. SQLite-файл локально.
- ❌ Реальная авторизация. Прокинутый `user_id=1` в демо.
- ❌ Push-уведомления через FCM/APNs. Симулируются в UI.
- ❌ Реальное подключение к Apple Watch / Garmin. Только симуляция.
