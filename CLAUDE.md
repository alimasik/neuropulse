## 1. О проекте (контекст в одном абзаце)

**NeuroPulse** — это MVP цифрового ассистента **предиктивной десенсибилизации** для людей с РАС, синдромом Туретта и другими нейроотличными состояниями. Система собирает данные с носимых устройств (пульс, акселерометр), с помощью ML предсказывает приближение сенсорного срыва (мелтдауна) за 10–15 минут и предлагает интервенцию: дыхательные практики, "тихий маршрут", невербальные AAC-карточки для коммуникации с окружающими. Проект делается на **хакатоне за ограниченное время**, поэтому приоритет — наглядное демо, а не production.

Полный контекст кейса — `docs/case-context.md`. Архитектура — `docs/architecture.md`.

## 2. Технологический стек (зафиксирован, не менять без согласия)

| Слой | Технология | Зачем |
| --- | --- | --- |
| Frontend (демо) | **Vite + React + TypeScript** | Лёгкий SPA, эмулирует мобильный UI на десктопе для презентации |
| Стилизация | **Tailwind CSS** | Быстрая верстка, не тащить отдельный CSS-фреймворк |
| Backend | **FastAPI (Python 3.10+)** | Минимум кода, авто-Swagger для жюри |
| База данных | **SQLite** | Один файл, без отдельного сервера |
| ML | **scikit-learn / XGBoost** + numpy/pandas | Классические модели для табличных временных рядов, без TensorFlow |
| Симуляция данных | **Python-генератор** (см. `data/`) | Синтетика биометрии — реальные wearable не нужны для демо |
| Графики | **Recharts** (frontend) / **matplotlib** (notebook) | Никаких тяжёлых D3 |

**Запрещено:** Docker (тратит время на хакатоне), Kubernetes, монорепо-инструменты (turbo/nx), Redis, PostgreSQL, Kafka. Если кажется, что нужно — спроси пользователя.

## 4. Глобальные правила работы (для Claude Code)

### 4.1. Перед изменением — прочитай локальный CLAUDE.md
В каждой ключевой папке есть свой `CLAUDE.md` с правилами этого слоя. **Всегда читай его перед изменением файлов в этой папке.** Корневой CLAUDE.md задаёт общие правила, локальные — уточняют.

### 4.2. Сначала план, потом код
Перед нетривиальной задачей опиши план (2–6 шагов) в чате и дождись подтверждения. Для тривиальных правок (опечатка, мелкий рефакторинг) план не нужен.

### 4.3. Минимализм
Хакатон — это не production. Не добавляй абстракции "на будущее", не вводи паттерны Repository/UnitOfWork/CQRS, не пиши тесты на каждую функцию. Тесты — только для ML-инференса и критичных API-эндпоинтов.

### 4.4. Доступность — это не опция, а ядро продукта
Это медтех-кейс для людей с сенсорной чувствительностью. **Любой UI-элемент проверяется по `docs/ux-guidelines.md`** (контраст, размер тапа, отсутствие резких анимаций, пастельная палитра). Если ты добавляешь компонент и не уверен — спроси.

### 4.5. Никаких реальных медданных
Все биометрические данные — **синтетика**. Не подключайся к реальным API носимых устройств. Не сохраняй персональные данные. В `.env.example` — только заглушки.

### 4.6. Демо-ориентированность
Каждая фича должна быть **видна на экране за 5 минут питча**. Если фича не отражена в UI или дашборде — она не существует.

### 4.7. Коммиты
Conventional commits на русском: `feat:`, `fix:`, `docs:`, `refactor:`, `style:`. Сообщение — что и зачем, не "wip".

## 8. Что НЕ делать (короткий чек-лист запретов)

- ❌ Не добавлять зависимости без явной необходимости (особенно тяжёлые: tensorflow, torch, transformers).
- ❌ Не использовать мигающие/резко-контрастные UI-элементы (триггеры для РАС).
- ❌ Не писать заглушки вида `# TODO: implement` в финальном коде — либо реализуй, либо удали.
- ❌ Не коммитить `node_modules/`, `.venv/`, `*.db`, `__pycache__/`.
- ❌ Не использовать `console.log`/`print` в **прикладном коде** (frontend, backend, ml_core) — только логгер. **Исключение:** CLI-скрипты в `scripts/` могут (и должны) выводить прогресс через `print`/`echo` — это их пользовательский интерфейс.
